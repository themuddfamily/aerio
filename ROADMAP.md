# Aerio development roadmap

Updated: 2026-10-17. Remaining tasks that can be assigned to Codex. Each task includes implementation, appropriate automated checks, and documentation updates.

## eM Client feature parity

These additions come from REA inspection of the installed eM Client 11.0.1201 package, corroborated with official feature documentation and compared with Aerio's current source. [Evidence, implementation boundaries, and limitations](docs/em-client-parity.md) map each E-number below to its sources. The checkbox scope describes proposed Aerio behavior; it does not claim that every detail was observed in eM Client. Existing scheduled send, Undo Send, snooze, rules, translation, message tools, writable Calendar/Contacts, and connected Tasks remain implemented.

### Composition and follow-up

- [x] **E01: QuickText and message templates.** Add reusable named snippets and whole-message templates with subject, sanitized HTML, and managed attachments; support insertion, editing, search, and backup/restore. Preserve editor selection and verify template reuse across draft autosave and restart. Snippets and whole-message templates live in `mail-templates.sqlite` with subject, HTML re-sanitized on every save/restore, and managed attachment copies (10 files/20 MB per template). A composer picker searches, inserts at the preserved editor selection, edits, deletes, saves the current selection or message, and exports/restores standalone backups; local-data backups also embed templates with two-phase restore. Inserted attachments are staged into each draft, so template edits never alter existing drafts. Vitest covers real-SQLite persistence across reopen, files, tampered backups, IPC/backup wiring, preload and in-composer autosave; native `execCommand` undo, packaged-app use and live-provider delivery are unverified.
- [x] **E02: Sender aliases and signature management.** Support provider-authorized From identities, Reply-To, multiple HTML signatures, and per-identity defaults for new messages and replies. Replace signatures without duplicating quoted content, preserve the selected identity in drafts, and verify provider permission failures. Sender identities discover Gmail send-as aliases (with signatures) and Microsoft proxy-address aliases, and accept manual IMAP/shared-mailbox addresses; each has Reply-To, a default flag and separate sanitized HTML signatures for new messages and replies. The composer swaps only the marked signature block when From changes, so quoted content is never duplicated; drafts keep identity and Reply-To, SMTP uses the alias as envelope sender, and provider refusals or unverified aliases leave a failed draft with a clear explanation instead of silently sending from the primary address. Real-SQLite store, provider parsing/error mapping, IPC/preload, worker send/refusal and composer/settings tests pass; live Gmail/Microsoft 365/SMTP behavior, Graph shared-mailbox discovery and identity backup are unverified or separate. See `docs/sender-identities.md`.
- [x] **E03: Richer message composition.** Add inline images with CID MIME parts, tables, fonts/colors, alignment, and sanitized rich-text paste. Keep plain-text alternatives and verify formatting, image references, and attachments survive autosave, reopen, and Gmail/Graph/SMTP delivery. A formatting toolbar adds fonts, sizes, text/highlight colors, alignment, lists, tables and inline images; HTML paste is sanitized with Office cleanup and Ctrl+Shift+V pastes plain text. One strict tag/attribute/CSS allowlist (`src/lib/mail-rich-text.ts`) applies on paste and again to every outgoing message, preserving signature/quote markers so rich signatures are no longer simplified. Inline images live in draft HTML as Content-ID-tagged data URLs (surviving autosave, reopen and backups) and are emitted as deduplicated multipart/related parts beside the text/plain alternative and ordinary attachments for Gmail, Graph, IMAP drafts and SMTP; remote image sources are dropped. Unit tests cover the allowlist, Word paste, outgoing sanitizer/CID conversion, parsed MIME structure, toolbar/paste/drop limits and composer autosave/reopen; recipient rendering, live delivery, real-Chromium editing and re-importing other clients' cid: images are unverified. See `docs/rich-composition.md`.
- [x] **E04: Personalized mass mail.** Expand a contact selection into separate recipient deliveries with previewable variables and fallback values. Track progress and cancellation per recipient; verify address privacy, provider limits, restart recovery, and ambiguous-send review before enabling bulk sending. Mail merge expands selected contacts or a pasted address list/CSV into separate single-To deliveries (no Cc/Bcc fan-out, verified before sending) with HTML-escaped `{{variable|fallback}}` substitution, header-safe subjects and a per-recipient preview shared with the sender. A confirm step shows counts and conservative per-provider per-minute and rolling daily limits, with back-off on rate-limit responses. Per-recipient state is durable in SQLite: a send interrupted mid-submission, or a profile restore, is held as ambiguous for Resend/Skip review and never retried automatically. Tests cover substitution/escaping, MIME privacy, throttling, daily caps, back-off, error classification, reopen recovery, worker end-to-end with mocked Gmail, IPC, restore holds and UI; live provider sending, real rate-limit responses, OpenPGP merges and per-recipient attachments are unverified or out of scope. See `docs/mail-merge.md`.
- [x] **E05: Watch for replies.** Persist watches on outgoing messages, notify when a matching reply arrives or a deadline expires, and allow cancellation. Match using message references and account identity; verify unrelated messages, multiple recipients, offline sync, restart, and tray processing. Reply watches persist in `mail_reply_watches` and are set from the composer or a sent message menu with an optional deadline; draft watches activate on delivery using the sent Message-ID and, for Gmail, the returned thread ID. The worker matches same-account synced mail by References or by provider thread when the sender was an original recipient, notifies from background/tray on reply or deadline, and lists/cancels watches under Mail › Reply watches; Undo Send or discard cancels the watch. Deadlines expire only after a post-deadline sync (or 24h grace). Real-SQLite tests cover unrelated mail, multiple recipients, account isolation, restart, offline deferral and tray notifications; Gmail Message-ID retention, Microsoft Sent-copy adoption and IMAP servers without stored Sent copies are unverified.
- [x] **E06: Receipts and outgoing importance.** Add read/delivery receipt requests, an incoming read-receipt policy, and outgoing priority controls. Preserve these choices in drafts and MIME/provider mappings; verify consent, unsupported provider behavior, and receipt correlation without treating receipts as guaranteed delivery or reading. The composer sets low/normal/high importance and read/delivery receipt requests, preserved with drafts and mapped to MIME headers (Importance/X-Priority, Disposition-Notification-To, Return-Receipt-To), Graph `importance`/receipt flags and SMTP DSN; Gmail delivery receipts are reported unsupported. Incoming receipt requests follow a Never / Ask (default) / Always policy enforced in the main process; Always still asks for junk, automated, multi-address or mismatched Return-Path requests (RFC 8098), each message is answered at most once, and returned MDNs/DSNs are correlated with sent mail without claiming guaranteed delivery or reading. Vitest covers parsing, consent, policy, provider mapping, persistence, IPC and UI; Gmail header retention, Graph PATCH on MIME-uploaded drafts, Exchange receipt formats and live DSN behavior are unverified. See `docs/mail-receipts-and-importance.md`.

### Message privacy and security

- [x] **E07: OpenPGP mail.** Implement signing, encryption, decryption, and signature verification, including key import/export, recipient key selection, trust details, and protected private-key storage. Verify interoperability, attachments, missing/expired/revoked keys, app-lock behavior, and refusal to silently send plaintext after encryption fails. OpenPGP.js 6.3.2 in the main process signs, encrypts, decrypts and verifies PGP/MIME (RFC 3156) plus read-only inline PGP, with key generation, armored/binary import/export, per-recipient key selection, fingerprint/user ID/expiry/revocation details and manual verification. Private keys are stored only passphrase-encrypted inside a safeStorage-wrapped keyring that is excluded from profile backups; unlocked keys are cached for ten minutes and cleared on app lock, which also refuses all private-key operations. Send and schedule preflight recipient and signing keys, and any crypto failure aborts delivery with the draft kept; encrypted drafts are never uploaded as provider plaintext. Unit tests cover library-generated round trips, nested sign-then-encrypt, attachments, missing/expired/revoked keys, lock behavior and plaintext refusal; GnuPG/Thunderbird interoperability, live delivery (including Graph MIME upload), protected headers, Autocrypt and key discovery are unverified or out of scope. See `docs/openpgp-mail.md`.
- [ ] **E08: S/MIME mail.** Add certificate import/selection, signed and encrypted MIME handling, certificate-chain/status presentation, and protected private keys. Verify signed-only and encrypted round trips, incorrect recipients, expiration, untrusted chains, and backup/recovery boundaries with controlled certificate fixtures.
- [x] **E09: Tracking-pixel protection.** Detect and explain suspected tracking resources and retain their blocking when a user permits other remote images. Extend the existing isolated image-fetch pipeline; verify allow/block choices, redirect handling, and that classification does not fetch remote content. `electron/mail/tracking-protection.ts` classifies remote images from markup and URL text only (tiny/hidden dimensions, known tracker hosts, open-tracking paths); suspected trackers keep an explanatory placeholder and never reach the image proxy, even after remote images are permitted. A per-message notice lists tracker hosts and reasons. `electron/mail/remote-image-fetch.ts` follows redirects manually without cookies, re-validating scheme, credentials, private DNS and tracker status for at most five hops. Unit tests cover classification, allow/block, mocked redirects and the notice; live `net.fetch` redirect behavior is unverified. See `docs/tracking-protection.md`.
- [x] **E10: Mailing-list unsubscribe.** Parse List-Unsubscribe and one-click unsubscribe metadata and present an explicit action with the destination visible. Support applicable HTTPS and mailto flows; verify malformed headers, redirects, failures, and that merely viewing a message never unsubscribes. `electron/mail/list-unsubscribe.ts` parses RFC 2369/8058 headers from stored original headers only when the user chooses "Unsubscribe from list…"; the dialog shows every HTTPS/mailto destination before acting. One-click sends a cookie-free POST without following redirects and refuses private hosts; users may instead open the link or queue an unsubscribe email from the receiving account. The main process re-reads headers per action and accepts only listed destinations. Unit tests cover malformed/insecure headers, redirects, HTTP/network failures, private hosts, unlisted URIs, archived accounts and viewing without side effects. DKIM coverage of the headers, DNS-rebinding pinning and live list servers are unverified; see `docs/mailing-list-unsubscribe.md`.

### Search and mailbox organization

- [x] **E11: Saved search folders and richer queries.** Persist named searches with account/folder scope, filters, phrases, and explicit AND/OR/NOT semantics. Build on the current offline index and filter panel; verify query validation, live result updates, pagination, and persistence across restart. A safe parser (`src/lib/mail-search-query.ts`) supports quoted phrases, AND/OR/NOT and `-term`, parentheses and from:/to:/cc:/subject:/body:/attachment: prefixes, compiling to re-quoted FTS5 MATCH strings bound only as parameters; invalid queries show inline errors. Named searches with account, mailbox, label and filter scope persist in `mail_saved_searches`, are validated before IPC and appear under "Saved searches" in the sidebar. Tests cover parsing/validation, real SQLite Boolean results, injection-shaped input, exclusion-only paging/totals, live updates after indexing, reopen persistence, account-deletion cascade, IPC and UI. Large-scale FTS performance of exclusion subqueries and per-search counts remain outside scope; see `docs/mail-search.md`.
- [x] **E12: All-attachments workspace.** Browse attachments across accounts with sender/recipient, date, file type, and size filters, plus open/save actions and navigation to the original message. Reuse managed attachment access and verify pagination, unavailable files, archived accounts, and account deletion. An "All attachments" workspace from the Mail sidebar lists cached attachment metadata across accounts with name, sender, recipient, account, date, file-type and size filters, keyset pagination, and exclusion of Trash/Spam, duplicate copies and (by default) inline Content-ID images. Rows open or save through the existing per-message IPC or open the original message; rows whose original is not stored offline are disabled and labelled, archived accounts are badged, and deleted accounts drop out by cascade. Unit tests cover filters, states, tied-timestamp and 8,000-row paging, IPC routing and the UI; very large real mailboxes (no dedicated index) and packaged OS-default opening are unverified. See `docs/attachments-workspace.md`.
- [x] **E13: Attachment-content search.** Add bounded local text extraction for supported PDF, Office, and text attachments and index extracted content alongside existing filename search. Isolate parsers, expose unsupported/encrypted files, and verify resource limits, incremental reindexing, cancellation, and index removal on account deletion. PDF, docx/xlsx/pptx and text/HTML attachments are extracted locally by built-in bounded parsers in an isolated worker thread (256 MB heap, 15 s per file, 25 MB input, 64 MB inflation, 5,000 zip entries, per-attachment/message character caps) and indexed with the message, so `attachment:` and unscoped searches match file contents while `body:` does not. Encrypted, oversized and unreadable files are reported in the reader; indexing is incremental and versioned, cancellable per account, and removed with messages and accounts. Tests cover each parser including zip/PDF bomb limits and encryption detection, real worker hangs/OOM/crashes/cancellation, and real-SQLite indexing, reindexing and deletion; packaged asar worker loading, very large mailboxes, OCR, legacy Office/RTF/archive formats and retries of failed files are unverified or out of scope. See `docs/mail-search.md`.
- [x] **E14: Folder and label management.** Add create, rename, delete, nesting, and supported color changes for provider folders/labels. Apply provider capability and system-folder restrictions, preserve queued operations and selections, and verify conflicts, offline recovery, and failed deletions without losing messages. A "Folders & labels" dialog creates, renames, nests, recolors (Gmail palette) and deletes Gmail labels, Microsoft Graph mailFolders and IMAP folders; system folders are locked. Non-empty deletes require confirmation against the live provider count, IMAP deletes move messages to Trash and verify emptiness first, and deletion is blocked by subfolders or queued operations. IMAP renames rewrite cached messages, queued operations, undo snapshots, rules and checkpoints, and journaled provider requests are reconciled after restart. Real-SQLite, client, component and loopback IMAP integration tests (create, sync, rename, refused unconfirmed delete, Trash delete) pass; folder changes require connectivity rather than queueing, and live Gmail/Graph behavior is unverified. See `docs/mail-folder-management.md`.
- [x] **E15: Advanced and server-side rules.** Extend local rules with richer conditions/exceptions and outgoing processing, then add supported Gmail and Microsoft server-rule management with capability reporting. Keep local and server execution explicit; verify loop prevention, unsupported mappings, permissions, and that one message is not processed twice. Local rules add Cc, named-header, attachment, size, age, importance and folder/label conditions, "except if" exceptions and an outgoing trigger on newly synced Sent mail; a per-account, per-trigger Message-ID ledger processes each message once across resyncs, IMAP moves and overlapping history passes, and rule actions never send mail, preventing loops. Gmail filters and Outlook inbox rules can be listed, uploaded, replaced/updated, toggled (Outlook) and removed, with blocking/approximate mapping reports shown before upload and rechecked in the main process; uploaded rules run only on the server, and a shared scope helper explains missing `gmail.settings.basic`/`MailboxSettings.ReadWrite` grants with a reconnect path. Unit, SQLite, worker, IPC and UI tests use mocked provider HTTP; live Gmail search-string acceptance, Graph size boundaries, mixed Outlook exceptions and IMAP ManageSieve are unverified or unsupported. See `docs/mail-rules.md`.
- [x] **E16: User-defined Quick Actions.** Let users save named sequences of existing mail actions and run them from the toolbar, context menu, or a shortcut. Reuse queued mutations and Undo; verify ordering, partial failure, read-only accounts, multi-selection, and persistence. The existing command palette and individual quick-action buttons do not supply saved macros. Saved Quick Actions (up to ten ordered steps from the existing action vocabulary, optional account scope, Ctrl/Cmd+Shift+1–9 shortcut and toolbar flag) persist in `mail_quick_actions` and run from the selection and reader toolbars, the conversation context menu, shortcuts and the Ctrl+K palette. Each account is preflighted for missing, read-only, out-of-scope or stale destinations, steps queue through existing mutations with Undo (now reverted newest-first; same-millisecond operations dispatch in creation order), and a failed step stops that account and is reported. Tests cover ordering, reverse Undo, multi-account selection, skips, partial failure, reopen persistence, unique shortcuts, IPC/worker routing, UI and palette; live providers, provider-side failures after retries and Microsoft category steps are unverified. See `docs/mail-quick-actions.md`.
- [x] **E17: Automatic replies.** Add provider-backed out-of-office replies with date ranges and supported internal/external audience settings. Read back the active server configuration, explain unsupported accounts, and verify permission errors, time-zone conversion, updates, and disabling independently of Aerio remaining open. Account settings read back and edit provider-side automatic replies through Gmail `users.settings.vacation` and Graph `mailboxSettings.automaticRepliesSetting`, re-reading the server after every save or disable so the UI shows stored state. Date ranges convert local time to UTC and Exchange Windows/IANA zones with DST rules; audiences cover Gmail contacts/domain and Microsoft internal/external messages; replies can be disabled while keeping their text, and the UI explains that providers reply whether or not Aerio is open. IMAP and non-Graph mailboxes are explained as unsupported; missing `gmail.settings.basic`/`MailboxSettings.ReadWrite` grants are detected from stored scopes or 403s with a reconnect path, while existing grants and background refresh are unchanged. Mocked Gmail/Graph unit tests cover mapping, time zones, permissions and UI; live accounts, Google consent-screen configuration for the new scope, outlook.com mailboxes and admin-blocked consent are unverified; see `docs/automatic-replies.md`.

### Mail portability and storage

- [x] **E18: Mail import and writable local folders.** Import EML/MBOX and Outlook PST into a provider-independent local mail store, retaining folder hierarchy, dates, flags, MIME, and attachments. Provide progress, cancellation, duplicate review, restart recovery, and controlled fixtures; existing single-message EML export and disconnected-account archives remain supported. A provider-free Local Folders account supports offline folder create/rename/nest/delete, read/star/move/Trash with Undo, and copy/move from other accounts. Streamed MBOX/EML trees (including Thunderbird `.sbd` and Apple Mail `.mbox`) and Outlook PST/OST files (pst-extractor 1.12.0 in the mail worker: Unicode PST, compressible encryption, Outlook 2013+ OST) import with folder hierarchy, dates, read/flag state, senders/recipients, plain/HTML bodies (compressed RTF decompressed and HTML de-encapsulated) and attachments, Outlook items being rebuilt as deterministic MIME. Imports provide progress, pause/cancel, size/disk limits, restart-resumable cursors (byte offset or PST folder+item) and SHA-256/Message-ID duplicate review; a crash-replay miscount of failed items was fixed. Tests use generated MBOX/EML fixtures, the sample PST/OSTs shipped with pst-extractor, mocked MAPI items and the official MS-OXRTFCP vectors. ANSI PSTs, real HTML-in-RTF bodies, newer/locked or damaged OSTs, non-Western code pages, real Thunderbird/Apple Mail/Takeout exports and multi-gigabyte archives are unverified; high-encryption PSTs and `.msg`/`.emlx` are rejected with an explanation. See `docs/mail-import-local-folders.md`.
- [x] **E19: Scheduled full-profile backup and restore.** Extend local-module backups to cover mail, local folders, drafts, queued operations, rules, templates, and preferences with a consistent snapshot, retention, and restore preview. Define credential/key exclusions and account reauthorization; verify corruption, migration, interrupted restore, and prevention of unintended queued sends after recovery. Scheduled (daily/3-day/weekly) and manual full-profile backups snapshot each allowlisted database (state, mail cache/drafts/queues/rules/Quick Actions/watches, message store, templates, productivity, provider tasks) with SQLite online backup, integrity checks and a SHA-256 manifest, plus managed mail, note and template files, with keep-N retention and a verified restore preview. OAuth vaults, IMAP passwords, secure-storage blobs and the app-lock verifier are never included; restore stages and migrates the copy, holds outgoing/scheduled sends and connected-task writes for review, marks accounts for reauthorization, then swaps atomically on relaunch with automatic rollback after failures or a crash mid-swap. Real-SQLite tests cover exclusions, consistency during writes, corrupt/edited/unsafe manifests, newer/older schemas, rollback, crash recovery, held sends, path rebasing, retention, IPC rules and UI; databases are snapshotted sequentially, backups are unencrypted at rest, and an end-to-end Electron relaunch audit is not yet added. See `docs/profile-backup.md`.
- [x] **E20: Cloud attachments.** Add optional cloud-storage connectors that select/upload files and insert sharing links, starting with Google Drive and OneDrive. Show sharing scope before insertion, preserve ordinary attachments as an option, and verify cancellation, upload recovery, expired links, and revoked permissions. The composer uploads files to Google Drive (`drive.file`) or OneDrive (`Files.ReadWrite`) in resumable 5 MiB chunks from the main process and inserts a plain sharing link; the scope (anyone, OneDrive organization, or recipients only; view or edit) is shown before upload, oversized attachments receive a "share as cloud link" offer, and ordinary attachments remain available. Storage consent is added only by an explicit reconnect that preserves existing grants. Uploads can be cancelled, recover from dropped chunks, resume after restart from an encrypted session record (or are cleared when expired/changed/revoked), and Aerio-created links are re-checked before send for deleted files, revoked permissions and expired links. Mocked-fetch tests cover uploads, sharing, refusals, cancel/retry/resume, expiry, verification, vault scopes, preload and composer UI; live accounts, Google consent-screen setup, tenant link policies and in-app disconnect are unverified or out of scope. See `docs/cloud-attachments.md`.

### Calendar and contacts

- [x] **E21: CalDAV and CardDAV.** Add calendar/contact accounts for iCloud, Fastmail, Nextcloud, and generic DAV services, including discovery, capabilities, revisions, incremental sync, offline writes, and conflicts. Reuse the productivity contract and verify read-only/shared collections and server-specific behavior with controlled fixtures; current IMAP presets provide mail only. CalDAV/CardDAV accounts (iCloud, Fastmail, Nextcloud and generic presets) use RFC 6764 `.well-known` → principal → home-set discovery, detect read-only/shared/task-only collections, sync incrementally with RFC 6578 sync-collection (ctag+ETag fallback and multiget), queue offline writes durably with If-Match/If-None-Match, and send 412 or deleted-on-server results to conflict review without silent overwrites. Payloads reuse the ICS/vCard code and preserve unedited properties; requests stay on the account's own sites over HTTPS (loopback excepted), and app passwords live in OS secure storage outside backups, with restored accounts re-prompting and holding queued writes. Real HTTP/XML/SQLite tests run against an in-process loopback DAV fixture server, plus unit, IPC, backup-restore and Settings UI tests; real server quirks, CalDAV scheduling/free-busy, VTODO, Digest/OAuth auth and field-level conflict merging are unverified or out of scope. See `docs/caldav-carddav.md`.
- [x] **E22: Complete meeting invitation lifecycle.** Preserve organizer, attendee roles, resource attendees, and response status; handle incoming invitations, updates, and cancellations and offer accept/tentative/decline and supported proposed-time responses. Extend current event creation with attendees; verify iTIP/MIME and provider response flows, duplicate invitations, permissions, and stale updates. Events preserve organizer, attendee roles (CHAIR/REQ/OPT/NON-PARTICIPANT), rooms/resources (CUTYPE), PARTSTAT, RSVP and SEQUENCE across Google, Microsoft and ICS in an optional `attendeeDetails` field, while plain attendee strings remain supported; the editor has required, optional and room/resource fields. Incoming iTIP REQUEST/CANCEL/REPLY/COUNTER parts show a notice with Accept/Tentative/Decline, comment and proposed time, answered through Google `events.patch` (`sendUpdates=all`), Graph accept/tentativelyAccept/decline with `proposedNewTime`, or a mailed `text/calendar` REPLY/COUNTER; duplicate (UID+SEQUENCE+DTSTAMP) and stale updates are explained rather than applied. Vitest covers parsing, state decisions, provider and mailed responses, cancellations and UI with mocked requests; real organizer handling of mailed replies, Graph `uid` delta matching, Google time proposals, offline-queued replies and automatic application of incoming REPLY/COUNTER are unverified or out of scope. See `docs/meeting-invitations.md`.
- [x] **E23: Scheduling assistant.** Add provider-backed free/busy lookup and a timeline for required/optional attendees and resources. Distinguish unavailable data from free time, support working hours and time zones, and verify mixed accounts, permission denial, and provider failures. A scheduling assistant opened from the event editor queries the organizer calendar's provider (Google `freeBusy`, Graph `getSchedule`) for required/optional attendees and resources, showing hatched "unknown" rows for external, unshared, missing-permission and failed lookups instead of free time. It applies Graph and user working hours, displays the event zone plus an optional secondary zone, and suggests next slots where all known required attendees are free. Missing Google `calendar.freebusy` or Graph calendar scopes are detected via stored scopes or 403s with a reconnect path. Mocked-fetch tests cover request batching, per-attendee errors, mixed accounts, permission denial, 5xx/rate limits, network failures, local calendars, suggestion/time-zone logic and UI; CalDAV free-busy is unsupported, attendee roles are not yet persisted to providers, and real-tenant behavior is unverified. See `docs/scheduling-assistant.md`.
- [x] **E24: Advanced event recurrence and time zones.** Preserve named zones, all-day dates, recurrence intervals/end conditions, exceptions, and series identities; offer edit/delete occurrence versus series and secondary calendar time-zone display. Verify DST transitions, travel between zones, provider round trips, and unsupported recurrence preservation. A bounded RFC 5545 expander (`src/lib/recurrence.ts`) renders local series in every Calendar view with COUNT/UNTIL, intervals, BYDAY/BYMONTHDAY/BYMONTH/BYSETPOS, yearly and leap-day rules, EXDATEs and overrides in the event's named zone; unsupported rule parts are preserved unchanged rather than simplified. Events keep named zones and all-day dates, the editor has zone-aware inputs and an honest custom-repeat builder, and week/day views can show a secondary zone. Edits and deletes offer this event / this and following / all events for local calendars, Google (recurringEventId, originalStartTime, RRULE/EXDATE) and Microsoft (seriesMasterId, originalStart, patternedRecurrence). Unit tests cover New York and London DST (including nonexistent local times), travel between viewer zones, all-day dates, series edit plans and mocked provider round trips; live provider series semantics, RDATE expansion and editing synced provider repeat patterns are unverified or out of scope. See `docs/calendar-recurrence-time-zones.md`.
- [x] **E25: Online meeting integration.** Create, update, and join provider-backed conference meetings from calendar events, starting with Google Meet and Microsoft Teams and leaving a connector boundary for Zoom/Webex. Verify required consent, capability reporting, duplicate creation after retries, and preservation of existing conference details during edits. Google Meet (conferenceData createRequest with `conferenceDataVersion=1`) and Microsoft Teams (`isOnlineMeeting`/`teamsForBusiness`, `onlineMeeting.joinUrl`) can be added to provider events from the editor and joined through an https host allowlist that confirms before opening other hosts. Calendars report allowed meeting types from Google `allowedConferenceSolutionTypes` and Graph `allowedOnlineMeetingProviders`, explaining unsupported personal/Workspace cases; Zoom/Webex sit behind an `OnlineMeetingConnector` boundary as not connected. A stable request id persisted before the write, Google 409 recovery and existing-meeting checks prevent duplicates on retry, and unrelated edits never drop conference details. Unit, connector and UI tests mock fetch; live Graph delta/transactionId behavior, Google removal semantics and Workspace policy reporting are unverified. See `docs/online-meetings.md`.
- [x] **E26: Calendar/contact interchange.** Import/export ICS and vCard, subscribe to read-only internet calendars, and add CSV contact mapping with preview and duplicate handling. Preserve time zones, recurrence, multiple contact fields, and source identity; verify malformed files, refresh failures, and round trips separately from existing JSON backups. Dependency-free ICS (RFC 5545) and vCard 3.0/4.0 (2.1 best-effort) parsers/serializers plus CSV contact import/export handle folding, escaping, IANA/Windows/VTIMEZONE zones, all-day dates, recurrence and exceptions, multiple typed contact fields and source UIDs under size/count limits. Imports preview into a chosen destination (new/existing local calendar, writable provider calendar, local or provider contacts) with CSV column mapping and update/skip/copy duplicate handling. Read-only https/webcal subscriptions fetch in the main process (10 MB/30 s, checked redirects), refresh every 15 minutes to daily and keep the last good copy on failure. Unit tests cover malformed files, limits, refresh failures and ICS/vCard/CSV round trips separately from JSON backups; provider imports keep only connector-supported fields, recurrence expansion in views and backup of local calendars/subscriptions remain separate work, and real feeds are unverified. See `docs/calendar-contact-interchange.md`.
- [x] **E27: Rich contacts and distribution lists.** Preserve multiple typed emails/phones, postal addresses, birthdays, and photos; add explicit distribution-list membership and provider-supported group management. Extend current flat contact groups and single-address editors without discarding unmapped provider fields; verify recipient expansion, read-only sources, and edit conflicts. Contacts keep multiple typed emails, phones and postal addresses with a primary choice, birthdays, photos and multiple groups; Google and Microsoft mappers read and write every value and merge edits into retained raw provider entries, and saves are checked against the revision the editor opened. Local distribution lists, Google contactGroups (full create/rename/delete/membership management) and Outlook categories act as lists that expand in To/Cc/Bcc with a member preview and a review stop before sending unexpanded names; vCard carries CATEGORIES and PHOTO. Unit, store, IPC and UI tests use mocks; live People/Graph behavior (error texts, field clears, slot and photo limits) is unverified, and Microsoft contactFolders, contact groups and photos are documented as unsupported. See `docs/rich-contacts.md`.
- [x] **E28: Contact merge and communication history.** Add duplicate detection with merge preview and reversible local changes, plus a contact view of related messages and attachment history across selected accounts. Keep identities and provider ownership explicit; verify false-positive matches, field preservation, permissions, pagination, and account removal. Duplicate detection scores pairs on exact email (Gmail-only dot folding), normalized phone and name similarity with confidence and reasons, and never merges automatically.
