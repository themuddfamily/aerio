# Aerio for iOS and Android

A native Expo SDK 58 / React Native 0.88 companion, with Expo Router navigation. It connects directly to Gmail and Microsoft Graph. It is a separate package and does not load the desktop website or desktop credentials.

## What works

- Native Google sign-in and Microsoft public-client authorization code + PKCE sign-in, account reconnect/removal, and multiple cached accounts.
- Account inboxes, unified cached inbox, local search, pagination and explicit foreground refresh. Up to 200 messages per account are retained in the encrypted cache.
- Offline plain-text reading; remote HTML, images, scripts and tracking resources never render. Attachment names are shown, with downloading deferred to the provider app.
- Compose and reply, autosaved encrypted local drafts, explicit send confirmation, and provider-native read/unread, star/unstar, archive and Trash actions.
- Durable delivery review. Authentication failures leave a draft unsent; confirmed provider refusals are retryable. Lost responses, ambiguous server failures and interrupted submissions become **uncertain**, with no automatic send replay. A new copy requires an explicit warning and remains unsent until Send is pressed. A provider acceptance is not proof of final delivery.
- Mailbox changes queue while offline and run on explicit inbox refresh. Interrupted/ambiguous changes require review; they are never automatically repeated. Drafts never send on refresh, startup or reconnect.
- SQLCipher-encrypted SQLite messages/drafts/settings; database keys and Microsoft tokens in device SecureStore; Google's SDK retains its own native sign-in session. Builds without SQLCipher fail closed rather than silently create a plaintext cache.
- Inactive/background privacy cover, native screenshot/app-switcher protection, network cancellation and generation-bound lifecycle guards. Device biometrics/passcode authenticate unlocking when enrolled. Devices with no enrolled lock show a visible warning; configure the device lock for authenticated app access.

The mobile companion does not yet include attachments, IMAP/EWS/DAV accounts, calendar/tasks/contacts/chat, desktop profiles, desktop settings synchronization, push notifications or background mail polling. It has an independent cache and drafts; it does not synchronize local drafts with the desktop app. Gmail/Graph server actions synchronize through your provider.

## Install and configure

Use Node 26 and `npm ci` inside `mobile/`. Native modules and SQLCipher require a custom native build; **Expo Go is unsupported**.

### Google

1. Create OAuth clients in a Google Cloud project and enable the Gmail API. Configure the consent screen and test users/verification appropriate to the Gmail modify scope.
2. Android: register package `dev.aerio.mobile` and the SHA-1 of the key signing your build. Set a web OAuth client ID as `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`, or enter it in the app's Accounts settings. Local builds use test signing; release signing needs its own registered SHA-1.
3. iOS: register bundle ID `dev.aerio.mobile`, and set `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID` before prebuilding. Its reversed client ID URL scheme is generated by the native Google config plugin and requires rebuilding when changed.
4. The Google SDK keeps one current native Google session. Other Gmail accounts remain readable offline; explicitly reconnect an account before refreshing it when another Google account is current. Each returned access token is verified against Gmail's mailbox profile before use, so a concurrent sign-in cannot apply an action to the wrong mailbox.

Google requests `https://www.googleapis.com/auth/gmail.modify`; no client secret or hosted backend is embedded in the app.

### Microsoft

1. Register an Entra application that supports your intended personal/organizational accounts. Under **Mobile and desktop applications**, register redirect `aerio://oauth/microsoft` and enable public-client flows. Do not configure a client secret for the native app.
2. Set `EXPO_PUBLIC_MICROSOFT_CLIENT_ID` and optionally `EXPO_PUBLIC_MICROSOFT_TENANT`, or enter them in Accounts. The tenant defaults to `common`; `organizations`, `consumers`, or a directory ID are supported.
3. Grant delegated `User.Read`, `Mail.ReadWrite`, `Mail.Send`, plus `openid`, `profile`, `offline_access`. Organizational consent policies may require an administrator.

Microsoft uses the system browser with state validation and S256 PKCE. Refresh tokens rotate in SecureStore, with serialized guarded writes and cleanup if the app locks during the keychain write. Only the public Microsoft cloud endpoints are supported.

## Development and native builds

```sh
npm ci
npm run check
npx expo install --check
npx expo prebuild
npm run android
# macOS + Xcode 26.4 or later (Expo SDK 58 requirement):
npm run ios
```

Native directories are generated and ignored. Configure native behavior in `app.json`, `app.config.ts` and config plugins; do not manually edit generated projects.

On Windows, Android's generated dependency object filenames exceed Ninja's 260-character path limit in the normal checkout. Use a real short build directory, not a junction or `subst` drive. The reproducible script copies the source into a dedicated marked workspace:

```powershell
$env:JAVA_HOME = 'C:/Program Files/Eclipse Adoptium/jdk-25.0.4.1-hotspot'
$env:Path = "$env:JAVA_HOME/bin;$env:Path"
$env:ANDROID_HOME = "$env:LOCALAPPDATA/Android/Sdk"
$env:AERIO_ANDROID_BUILD_ROOT = 'C:/am'
# Choose a new empty path; the script refuses unrelated existing folders.
npm run build:android
```

This creates a standalone locally signed APK and hash report in ignored `artifacts/`. For an emulator-only build set `AERIO_ANDROID_ARCH=x86_64`; leave it unset for the default device architectures. Local APK signing is for testing. Use `npx eas-cli@latest build --platform android --profile production` or the iOS equivalent with your own store signing credentials for distribution. No store release or OAuth production verification is implied by a successful local build.

## Validation and native evidence

`npm run check` runs strict TypeScript, Expo lint and independent Jest Expo tests. Tests exercise real SQLite persistence via Node's SQLite adapter, provider REST contracts and bounded streaming, nested MIME budgets, account isolation, token rotation, deferred lock/unlock and keychain races, native Google account switching, UI navigation/autosave/confirmation, and prevention of duplicate sends.

The native integration audit is enabled only in explicitly instrumented builds with `EXPO_PUBLIC_NATIVE_AUDIT=1`. It uses a **separate** encrypted `aerio-native-audit.db`, synthetic addresses and no network. It verifies actual SQLCipher presence, encrypted file bytes, native keychain roundtrip, offline close/reopen, lock continuation guards and uncertain-send recovery. It writes non-sensitive results to `Documents/aerio-native-audit.json` and shows a PASS/FAIL label. Never distribute an audit build as the production app.

- Android: a real x86_64 emulator Release build and runtime audit have passed locally. An ordinary Release APK with the audit disabled also runs without Metro, unlocks its encrypted cache and displays the native Inbox; its audit label, report and fixture database are absent. A signed ARM64 APK has also built successfully with the same embedded JavaScript bundle, but has not run on a physical ARM64 device. Local APKs, SHA256 proofs, build logs and native UI evidence are retained in ignored `artifacts/`. Debug development builds connect to Metro (`npm start`), with `adb reverse tcp:8081 tcp:8081` when needed. Emulator/provider OAuth login still requires registered public client IDs and explicit user sign-in; tests do not use real mailbox credentials or send real mail.
- iOS: `.github/workflows/mobile.yml` can run a macOS simulator compile and launch using `node scripts/ios-native-audit.mjs`, then upload the `.app`, audit JSON and simulator logs. It requires no App Store signing. The initial CI attempt exposed and corrected an Xcode invocation issue; the corrected run was cancelled at the user's request on 20 October 2026. **iOS native compilation/runtime remain unverified.** Windows can export an iOS JavaScript bundle but cannot compile or run iOS. Do not dispatch a new CI run until the user authorizes it.
