# Isolated application profiles

The **Profiles** button in the navigation rail opens the application profile switcher. Create named profiles such as Personal and Work, rename them, and switch between them. New profiles start empty. Switching saves the current preferences and local workspace, then restarts Aerio in the selected profile. Close draft editors and other Aerio windows first; switching is blocked while a detached message window or another visible Aerio window remains open. Profile creation and renaming never copy or delete data. Profile deletion is intentionally not exposed.

Each profile has a separate Electron `userData` and `sessionData` directory, selected before startup services or browser sessions initialize. This separates mail/productivity databases, preferences, accounts, OAuth/DAV/cloud credential vault files, encryption keys, attachments, drafts and schedules, chat storage, browser cookies/localStorage, MCP configuration and logs. Each profile can use its own app-lock passphrase. Only the active profile runs synchronization, background schedules and notifications. Profiles share the operating-system user and are not separate OS security identities.

The original profile remains in the existing application data directory and initially appears as Personal; no existing databases or credentials move. Additional profiles live under `profiles/<UUID>` in that original directory. An atomically written `app-profiles.json` registry records their names and the last-selected profile. Corrupt registries fail startup explicitly rather than silently opening a different or empty profile. Profile backups continue to cover only the active profile's configured backup files, not sibling profiles or the global registry.

Aerio remembers the last-selected profile on the next launch, including login startup. For an explicit startup selection, launch with `--aerio-profile=<UUID>` or `--aerio-profile=default` after quitting Aerio. `--user-data-dir=<directory>` remains the base directory for the registry and default profile; development and test overrides are retained across a switch. One single-instance lock remains at the base directory, so only one application profile runs at a time. Starting another instance while Aerio runs brings the current workspace forward. MCP configurations include their profile-specific endpoint; the executable bridge resolves the selected profile when no endpoint override was supplied.

Validation: `npx vitest run electron/app-profiles.test.ts src/components/AppProfileSwitcher.test.tsx src/App.test.tsx` plus preload coverage. `npm run build` and `node scripts/desktop-profiles-audit.mjs` verify actual isolated databases, settings, browser storage, remembered startup and original-profile preservation across four Electron launches.

Electron storage paths are configured before `ready` following the [Electron app API](https://www.electronjs.org/docs/latest/api/app).
