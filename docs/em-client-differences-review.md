# Aerio vs eM Client — differences to review

Reviewed: 2026-10-20. Aerio 0.5.0, commit `26d842d`.

- All D01–D34 additions were approved for implementation on 2026-10-20. Checkboxes below now track verified implementation, not approval. Each completed feature is committed and pushed separately; unchecked items remain outstanding.
- This is a starting review list based on current source, feature documents, previous REA evidence, and eM Client's current official documentation. It is not an exhaustive runtime comparison. Features advertised online may differ from the previously inspected eM Client 11.0.1201 package or require a particular plan.
- REA MCP is connected and responded as `rea-agents` 6.5.0. This pass checked its connection; it reused the [earlier artifact evidence](em-client-parity-followup.md) rather than claiming a fresh binary analysis.

## AI and email

- [ ] **D01 — In-app conversational AI assistant.** eM Client advertises an assistant that can organize mail and browse online. Aerio offers individual AI tools and a separate external MCP bridge. **Add:** a conversational assistant inside Aerio. Sources: [eM AI](https://www.emclient.com/ai), [Aerio AI](ai-assistance.md), [Aerio MCP](mcp-automation.md).
- [ ] **D02 — Create mail rules from plain English.** eM Client offers AI rule creation; Aerio's AI contract has no rule-generation action. **Add:** describe a rule, review its conditions/actions, then save it. Sources: [eM AI](https://www.emclient.com/ai), [Aerio AI contract](../src/ai-assistant-types.ts), [existing rules](mail-rules.md).
- [ ] **D03 — Saved AI writing style per account.** eM Client supports writing personalization from instructions and selected sent mail. Aerio accepts a prompt per draft but exposes no persistent style profile. **Add:** reusable account-specific writing preferences with optional style learning. Sources: [eM AI](https://www.emclient.com/ai), [Aerio AI contract](../src/ai-assistant-types.ts).
- [ ] **D04 — Detect tasks and events in email with AI.** eM Client offers automatic suggestions. Aerio documents manual create-from-email tools. **Add:** suggestions that prefill dates and details for review. Sources: [eM AI](https://www.emclient.com/ai), [Aerio AI](ai-assistance.md).
- [ ] **D05 — Show AI reply suggestions when opening mail.** eM Client can generate reply buttons on display; Aerio requires an explicit request. **Add:** an optional automatic suggestion setting. Sources: [eM AI](https://www.emclient.com/ai), [Aerio AI](ai-assistance.md).
- [ ] **D06 — Summarize a whole conversation with AI.** eM Client documents conversation summaries; Aerio's summary handler selects one message. **Add:** a summary across the selected thread. Sources: [eM AI](https://www.emclient.com/ai), [Aerio handler](../electron/mail/ai-assistant.ts).

## Further differences from the eM Client 11 release review

The eM Client side of D21–D34 is documented in the [official version 11 announcement](https://www.emclient.com/blog/em-client-11-has-been-released-842). Aerio findings below are bounded source-review findings, not runtime tests.

- [ ] **D21 — Sync app settings between devices.** eM Client offers eM Sync. Aerio has portable backup/restore, without a corresponding continuous settings-sync service. **Add:** optional synchronization of preferences, signatures, templates, and snippets. Aerio: [profile backup](profile-backup.md).
- [ ] **D22 — Synchronize message pins.** eM Client syncs pins on supported servers; Aerio explicitly keeps them local. **Add:** provider-backed pin synchronization where supported. Aerio: [pinning scope](mail-pinning.md).
- [ ] **D23 — Save sent replies beside the original.** eM Client offers this option; no equivalent setting was found in Aerio's account/draft contracts. **Add:** an account preference for reply filing. Aerio: [mail contracts](../src/mail-types.ts). **Status:** inferred gap; sending-path review needed before implementation.
- [ ] **D24 — Choose account subsets for unified folders.** eM Client supports configurable Global-folder membership. Aerio's reviewed mail UI selects all accounts or one account. **Add:** saved account subsets for unified views. Aerio: [mail view](../src/views/ConnectedMailView.tsx).
- [ ] **D25 — Configurable notification action buttons.** eM Client offers customizable actions; Aerio's new-mail notification opens the conversation. **Add:** user-selected notification actions and finer notification preferences. Aerio: [notification implementation](../electron/main.ts).
- [ ] **D26 — Customize the message toolbar.** eM Client offers toolbar customization. Aerio has selectable Quick Actions but no general message-toolbar layout editor was found. **Add:** choose and reorder visible message commands. Aerio: [mail view](../src/views/ConnectedMailView.tsx), [Quick Actions](mail-quick-actions.md). **Status:** inferred UI gap.
- [ ] **D27 — Switch between isolated app profiles.** eM Client supports profile switching. Aerio's profile editor changes the current user's details; it does not expose separate account/settings databases. **Add:** isolated personal/work profiles and a switcher. Aerio: [profile editor](../src/components/ProfileModal.tsx).
- [ ] **D28 — Authenticated proxy settings.** eM Client offers in-app proxy configuration. No corresponding Aerio setting or network-proxy integration was found in reviewed production source. **Add:** an explicit proxy configuration shared by supported connectors. Aerio: [Settings](../src/components/SettingsModal.tsx). OS/environment proxy behavior was not tested.
- [ ] **D29 — Run rules on archiving.** eM Client has an archive trigger; Aerio's rule-trigger type is incoming/outgoing. **Add:** an Archive trigger independent of automatic archiving policies. Aerio: [rule contracts](../src/mail-types.ts).
- [ ] **D30 — Run general rules periodically.** eM Client supports periodic rules; Aerio's recurring archive policy is separate from general incoming/outgoing rules. **Add:** scheduled evaluation of selected rules. Aerio: [rules](mail-rules.md), [automatic archiving](automatic-archiving.md).
- [ ] **D31 — Ready-made rule library.** eM Client offers rule presets. No preset library was found in Aerio's rule editor. **Add:** editable starter rules. Aerio: [rule editor](../src/components/MailRulesModal.tsx).
- [ ] **D32 — AppleScript integration.** eM Client supports AppleScript. Aerio exposes MCP, without an AppleScript interface found in reviewed main-process code. **Add:** macOS scripting support. Aerio: [main process](../electron/main.ts), [MCP](mcp-automation.md).
- [ ] **D33 — macOS Spotlight search.** eM Client integrates with Spotlight. Aerio has internal search; no Spotlight indexing integration was found in reviewed source. **Add:** optional system-search indexing and deep links. Aerio: [main process](../electron/main.ts), [platform assessment](platform-compatibility.md).
- [ ] **D34 — Multiple reminders per calendar event.** eM Client supports multiple reminders. Aerio's event model exposes one `reminderMinutes` value. **Add:** a list of event reminders with supported provider mappings. Aerio: [event model](../src/types.ts). Task reminders require a separate capability review.

## Existing overlap and other differences

- **Previous parity work is marked complete:** [ROADMAP.md](../ROADMAP.md) records E31–E48 as completed and identifies E01–E30 as completed historical work. Older evidence describes the gaps at the time; it must not be read as today's missing-feature list.
- **Already present in Aerio:** inbox categories, pins, favorite folders, Quick Actions, advanced rules, reply watching, scheduled delivery, Undo Send, templates, translation, attachment search, tracking protection, OpenPGP/S/MIME, imports/Local Folders, automatic archiving, duplicate cleanup, POP3, EWS/shared mailboxes, directories, DAV calendars/contacts/tasks, rich/server Notes, cloud attachments, Zoom/Webex, and MCP. See [README](../README.md), [roadmap](../ROADMAP.md), and the linked feature documents for implementation and validation limits.
- **AI behavior is a product choice:** Aerio defaults to off and runs AI on request, including support for Anthropic and OpenAI-compatible endpoints. D04/D05 would introduce optional automatic behavior. This checklist does not propose changing the defaults. See [Aerio AI](ai-assistance.md) and [eM AI behavior](https://www.emclient.com/ai).
- **Release readiness differs from having code:** Aerio remains an alpha with live-provider validation and registration work outstanding. Its macOS/Linux packages are experimental; non-Windows automatic updates are disabled. eM Client advertises Windows/macOS distribution. See [Aerio limitations](../README.md#current-limitations), [platform assessment](platform-compatibility.md), [update policy](../electron/update-policy.ts), and [eM platforms](https://www.emclient.com/features-overview). This is not a measured reliability or performance comparison.
