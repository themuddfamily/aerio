# Multiple calendar reminders (D34)

- The event editor can add, remove, and change up to five distinct reminder offsets, from 0 to 40,320 whole minutes before the event. Zero means at event time; removing every row disables reminders. Invalid or duplicate offsets prevent saving and are rejected at IPC/import boundaries.
- `CalendarEvent.reminders` is the authoritative list. Existing events without it continue to use `reminderMinutes` as a single reminder. The editor keeps that legacy field equal to the first offset, or zero when disabled. Local calendar storage, recurrence edits, and backup/import retain the list.
- Google writes every offset as a popup override (maximum five); disabled reminders send an empty override list. Reads resolve explicit overrides and calendar default reminder offsets. The list models notification times; Google email reminders become popup reminders when edited in Aerio. [Google event reminder fields](https://developers.google.com/workspace/calendar/api/v3/reference/events)
- ICS export writes one display `VALARM` per offset, including zero; import reads nonpositive, whole-minute, start-relative triggers. CalDAV uses the same mapping and retains original alarms when reminder offsets are unchanged. Absolute triggers, end-relative alarms, positive triggers, and alarms beyond the supported bounds are outside the editor's reminder model. Up to five supported offsets are imported.
- Microsoft Graph and Exchange EWS expose one native reminder. Their editors allow one row, including an at-start reminder or no reminder. Connector writes reject additional offsets with a clear error rather than silently dropping them. [Graph event fields](https://learn.microsoft.com/en-us/graph/api/resources/event?view=graph-rest-1.0)
- Aerio's desktop process delivers each calendar offset once while running, honoring the notification preference and hiding titles while the app is locked. The durable delivery state survives restart and profile backup/restore. Recurring local and CalDAV series are expanded with overrides and event time zones; Google/Microsoft instances use their synced occurrence times. Reminders up to one day late are caught up, preventing an imported calendar's full history from notifying. Closing Aerio prevents delivery until next launch; native provider reminders may also appear independently.
- Delivery refreshes at least once a minute, scheduling nearer known reminders more precisely. It considers starts from one day ago through 29 days ahead, covering the four-week maximum offset. Calendar notification snooze and a persistent reminder inbox are not provided by this change.

Validation covers editor interactions, legacy/disabled/zero semantics, untrusted list validation, Google and Microsoft mapping, Exchange limit enforcement, ICS and CalDAV round trips, local storage restart, recurring reminder delivery, and delivery deduplication across restart. These are controlled tests; live provider acceptance requires connected accounts.
