# Save sent replies beside their originals (D23)

- Enable **Save sent replies beside the original messages** in an account's settings. It defaults off and applies to new sent copies synchronized after enabling, including replies sent through other clients. It does not sweep existing mail. POP3/local archives are unsupported.
- Aerio waits for a synchronized Sent copy, matches its last References/In-Reply-To identifier to an original in the same account, and queues a message-specific folder operation. Gmail retains Sent membership and applies the original's Inbox and user labels. Folder providers move only the sent copy into the original's physical folder. Unrelated messages in the conversation remain untouched.
- Missing originals wait for a later download. Multiple physical source locations require manual filing and appear under **Replies awaiting filing** in account settings. Folder failures use the existing durable provider-operation queue; a local staging failure rolls back all operations and retries after synchronization. Disabling cancels unqueued pending filing; operations already in the mail queue retain their normal lifecycle.
- The filing ledger and queued changes live in the mail database and survive restart/backup. Message-ID identity prevents a moved/resynchronized copy from filing twice. Filing never sends mail, so it cannot repeat delivery after a folder error.
- This works with server-synchronized Sent copies. Some SMTP services do not retain a Sent copy automatically; without such a copy there is nothing to file. Cross-account originals and shared-mailbox destinations are outside this account-local flow. Gmail's label model keeps one logical message in several views rather than physically moving it out of Sent.

Validation covers opt-in/time boundaries, original/unrelated-message preservation, multiple Gmail labels, folder-provider moves, uncached originals, account isolation, restart/idempotence, ambiguous destinations and transactional rollback/retry. Provider operations reuse existing connectors; this change has not been validated against live accounts.
