# XMPP / Jabber chat (D10)

Chat's **XMPP / Jabber** connector uses the maintained [`@xmpp/client` 0.14.0](https://github.com/xmppjs/xmpp.js/tree/v0.14.0/packages/client) library for XML streams, verified TLS, SASL authentication, resource binding, IQ routing and stream-management acknowledgements. It is separate from Matrix; it does not enable the Matrix readiness gate or provide OMEMO/OTR/Matrix end-to-end encryption.

## Connect

- Use an existing XMPP account (`name@example.org`) and password. This connector does not register accounts. The optional endpoint defaults to `xmpp://example.org:5222` with **required STARTTLS**. Explicit `xmpps://server:5223` and `wss://server/path` endpoints are also supported. Plain `ws://` and embedded URL credentials are rejected. Certificate errors fail the connection; there is no trust-bypass control.
- Authentication runs only after actual TLS or WSS protection, including on localhost. A server that omits STARTTLS receives no password. The library negotiates SCRAM-SHA-1 or PLAIN over the verified protected connection; unsupported mechanisms fail explicitly.
- Applicable manual network proxies are currently unsupported for all XMPP transports, including WSS. Aerio rejects those connections before opening a socket, instead of silently connecting directly. Existing connections are closed when an operation observes the new proxy policy. Only hosts explicitly covered by your network bypass (including loopback) connect directly under manual mode. System proxy discovery is not promised for these library transports.
- Roster contacts become direct conversations. Add other contact JIDs in the comma-separated field when connecting/reconnecting. Existing MUC room JIDs can be configured separately, with an optional nickname. Each room must advertise MUC support before Aerio joins; Aerio does not create rooms. Password-protected rooms, invitations, room administration and roster editing are not exposed.
- Reconnect retains omitted account fields and a blank password; explicitly editing a contact/room field to empty clears that list. A connection identity includes the exact normalized endpoint plus bare JID. Changing endpoints is a new connection; passwords and provider metadata remain in main-process encrypted credential storage.

## Messages and capabilities

- Direct chat and MUC plain text are supported. Joining waits for self-presence; forbidden membership, nickname conflicts, read-only visitor roles and loss of membership disable sending or show room errors. Read markers, threaded views, presence controls, reactions, files and E2EE are unavailable in this connector.
- XEP-0030 discovery checks each account/room for `urn:xmpp:mam:2`. Advertised XEP-0313 archives are queried with XEP-0059 RSM pages of up to 50 messages. Cursors are scoped to a conversation; forwarded archive results require the expected archive identity, matching random query ID and matching participants/room. MUC archives remain subject to server membership/retention policy.
- Without an advertised archive, messages received in the current session are merged with Aerio's existing encrypted local history (bounded to 500 messages per latest cached conversation page). Aerio cannot recover messages that the server never archived and this client did not receive. The room explains its history capability. Server archive errors show cached history with an error, rather than claiming synchronization succeeded.
- Incoming stanzas are received on the authenticated connection. The shared workspace refreshes conversations and active messages every 30 seconds while unlocked/online; notifications and badges therefore follow that polling interval. XMPP unread indicators describe activity observed by this Aerio session and are not synchronized unread/read counts. MAM history alone does not establish unread state.
- Direct sends request XEP-0184 delivery receipts and can be confirmed by XEP-0198 server handling acknowledgements or a matching recipient receipt. MUC sends can also be confirmed by their matching room echo. **Sent** means the server handled the stanza (or an echo/receipt arrived), not that the recipient read it. Incoming direct receipt requests are answered as delivery acknowledgements, not read markers.
- A socket write alone is insufficient confirmation. Timeout/disconnection before confirmation leaves a durable **Delivery uncertain** record. Check the conversation before manually resending. The library's automatic reconnect/resume path is disabled; unacknowledged stanzas are never automatically replayed. Refresh opens a new authenticated connection. Startup converts interrupted `sending` records to review without sending them.

## Lock, cache and shutdown

The shared provider runtime's optional `suspend()` lifecycle closes persistent XMPP connections and clears volatile received-message buffers when the app locks, when offline polling runs, and during shutdown. Unlock/online refresh authenticates a new connection from the encrypted secret. Pending operations use generation guards, so account removal or suspension cannot resurrect a connection or return locked plaintext. A send already dispatched to the server may complete or become uncertain while locking.

Provider secrets and payloads use the separate encrypted provider chat vault/cache described in [the provider framework documentation](chat-teams-connector.md#local-storage-and-isolation). Cached identifiers/state timestamps remain structural metadata. Profile backup/import excludes these chat files. Typed IPC stays unavailable to the isolated Matrix service; tokens and library objects never enter renderer APIs.

## Validation

`npm run test:xmpp` runs [the real Prosody audit](../scripts/xmpp-prosody-audit.mjs). On Windows it requires an Ubuntu WSL distribution; on Linux it expects Ubuntu/Debian `apt-get`, `dpkg-deb` and standard libraries. It downloads/extracts Prosody/Lua packages under `/tmp/aerio-xmpp-audit-packages` without installing a system service, starts a unique temporary server/data directory on dedicated ports 15222/15223/15284, and removes that server's files/process on exit. Do not run concurrent copies on those ports. Package downloads are cached in the task's `/tmp` directory. Fixture credentials/certificates are disposable; production certificate validation stays enabled.

Verified against disposable Prosody **0.12.4**: real STARTTLS, direct TLS and WSS; SASL sign-in; untrusted-certificate and wrong-password rejection; roster mapping; two-user direct/MUC text round trips; fresh-connection MAM archive readback; encrypted local cache; lock suspension; forced socket interruption and restart review without replay. Fixture tests additionally cover missing TLS before authentication, malformed endpoints, unsupported history, cross-room/spoofed archive results, MUC permission errors, confirmation timeouts and shared UI wiring. No hosted-user account or arbitrary third-party server compatibility is claimed.
