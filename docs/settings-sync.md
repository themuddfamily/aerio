# Encrypted settings synchronization

Settings → **Settings synchronization** connects the active Aerio profile to a user-owned WebDAV file, such as a Nextcloud/ownCloud file URL. Create the destination folder first and enter its complete file URL, WebDAV user name/app password, a device name, and a shared encryption passphrase of at least 12 characters. Every device must use the same file and passphrase. Save the connection and explicitly enable scheduled synchronization; the default is off. **Sync settings now** runs immediately. Scheduled synchronization checks every configured 5–1440 minutes while Aerio is running and unlocked; it stops at conflicts until reviewed.

The portable snapshot includes appearance, custom themes, density, start module, read receipt policy, keyboard shortcuts, message toolbar, display profile and global notification preferences; reusable signatures, account signature text and existing sender signature assignments; whole-message templates, their attachment bytes, and QuickText snippets. Account/signature assignments match existing accounts by provider and email and existing sender addresses by email, so different device account IDs work. Missing accounts/aliases are not created. Their remote signature mappings are preserved when this device publishes other changes; newly connected accounts with conflicting mappings require review.

Credentials, account connection records, mail, tasks/contacts/notes, AI configuration, app-lock verifiers, proxy configuration, launch-at-login/tray choices, per-account notification overrides, and the sync connection itself stay local. The WebDAV password and encryption passphrase are saved with OS secure storage; Aerio refuses insecure storage fallbacks. They never appear in status responses or backups. Changing server/user requires re-entering the app password. The remote file, local checkpoint and interrupted-import recovery journal are encrypted with AES-256-GCM, independently generated 16-byte salts/12-byte nonces, and a 32-byte key derived with scrypt (N=32768, r=8, p=1). The passphrase cannot be recovered by Aerio.

Each version carries a format/schema version, unique revision, device name and timestamp inside its authenticated encrypted envelope. Uploads use strong ETags with `If-Match`, or `If-None-Match: *` for initial creation. Redirects, weak/missing ETags, non-HTTPS endpoints (except loopback test servers), embedded URL credentials, and blind overwrites are refused. Conditional-write races fail safely and require another sync. Older remote revisions or devices with clocks behind the previous revision require review. The server must support Basic authentication over HTTPS, GET, conditional PUT and strong ETags. No proprietary sync service is required.

On first connection to an existing file, or when both sides change, Aerio shows device/time, content counts and up to 100 changed preference/signature/template names. **Use this device's settings** publishes the complete portable snapshot; **Use shared settings** applies the shared one, including deletions. If either version changes after review, the choice is refused and a fresh review appears. Single-sided changes synchronize automatically after a common baseline is established. Local content is captured again after remote requests and asynchronous encryption; edits made in the meantime require a new review. Locking or closing Aerio aborts pending network work and prevents its continuations from applying data to closed stores. Preference/template snapshots are checked after each worker await, and signature updates and compensation compare the expected snapshot inside the database transaction. Compensation preserves newer user edits. An encrypted journal flags interrupted imports for explicit review against the current local and remote versions; it never automatically replays an older snapshot. The checkpoint records the exact imported baseline, so edits made while checkpoint encryption runs remain unsynchronized changes for the next pass. Template attachments and HTML are validated through the existing import path. Other profile data and sign-ins remain intact.

**Disconnect settings sync** stops this device and forgets its saved secrets/checkpoint, leaving local settings and the shared file intact. Revoke the WebDAV app password on your server to remove its server access; other devices use their own credentials. Deleting the shared file does not cause existing devices to recreate it automatically: they require explicit review before publishing again. To change the encryption passphrase, disconnect devices and use a new shared file, then reconnect them with the new passphrase. Server-side version history can retain previous encrypted files; restored older revisions enter review. Aerio's full-profile backups remain separate.

Limits: synchronized JSON is capped at 48 MiB before encryption (including base64 template attachments), and the encrypted transfer at 70 MiB. Oversized snapshots fail without truncating attachments. Snapshots replace the synchronized scope rather than merging simultaneously edited individual items. Scheduled sync requires Aerio to run; editors already open may need reopening to refresh their template/signature lists. Test coverage uses a local authenticated WebDAV fixture; live third-party servers still require their own interoperability checks.

Validation: `npm run build`; `npx vitest run electron/settings-sync.test.ts electron/settings-sync-data.test.ts electron/settings-sync-crypto.test.ts electron/settings-sync-webdav.test.ts src/components/SettingsSyncSection.test.tsx src/App.test.tsx electron/main.test.ts electron/preload.test.ts`; `npx tsx scripts/desktop-settings-sync-audit.mjs`. The native audit uses two Electron profiles and real conditional HTTP storage to verify encrypted bidirectional preferences/signatures/templates/QuickText, attachment bytes, secure credential persistence, and local disconnection.

Conditional requests follow [HTTP Semantics (RFC 9110)](https://www.rfc-editor.org/rfc/rfc9110.html#name-conditional-requests).
