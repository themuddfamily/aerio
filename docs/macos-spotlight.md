# macOS Spotlight mail indexing (D33)

**Settings → macOS Spotlight** enables actual Core Spotlight indexing for explicitly selected accounts. It is off by default, with no accounts selected; new accounts are never included automatically. Subjects and sender names are donated to the operating system. Message previews require their own checkbox. No message HTML, attachments, account credentials or provider tokens are indexed.

Spotlight is a separate operating-system index outside Aerio's encrypted stores. Indexed metadata can appear in system search and can remain while Aerio is closed. Locking or disabling requests deletion; macOS removes indexed results asynchronously, so this is not a guarantee of immediate secure erasure. If removal fails, Settings explains that metadata may remain and offers refresh. Decide whether system search is appropriate for each selected account before enabling it.

## Behavior

- Indexes up to the newest **10,000 locally cached conversations** in the selected active profile/accounts. Drafts, Spam and Trash are excluded. Unselected accounts and archived/removed accounts are excluded on every page. Previews are limited to 500 characters; subjects to 500, sender names/addresses to 320. This does not force downloads of uncached mail or index every individual message in a conversation.
- Refreshes after mail/account/delivery changes (two-second debounce), every five minutes while unlocked, and on explicit refresh. Each refresh replaces that profile's donated records so deleted conversations and changed scope are removed. An empty selection means no indexing. Core Spotlight expiration is seven days without refresh, as a fallback for abandoned installations; disabling is the immediate removal request.
- Uses opaque UUID item identifiers mapped locally to account/conversation IDs. The domain is unique to the local profile. No private account/thread identifiers are embedded in activation URLs. The mapping/settings database is device-local and excluded from profile backups and settings synchronization; restoring data does not opt a new device into indexing.
- Only the **active application profile** donates results. Profile switching pauses donations and awaits deletion of that profile's OS index before changing/relaunching; cleanup failure prevents the switch. Pending removal is persisted even after disabling or restarting, and refresh retries failed inactive-profile cleanup. Startup also removes the domains of registered inactive profiles, including a direct launch into another profile. A normal quit keeps the active profile's index for useful cold launching. Switching back rebuilds that profile's selected index.
- Handles Core Spotlight's `com.apple.corespotlightitem` continuation and the `aerio://spotlight/<UUID>` content URL. A valid result opens the existing conversation window through Aerio's mail service. While locked, only the UUID is retained; unlocking validates the selected account, live account ownership and conversation before opening. Removed/disabled/out-of-scope or unknown results are ignored. A stale UUID never opens a conversation in a different profile; OS removal remains asynchronous as described above.
- In-flight indexing and restoration have generation/lock checks. If a worker/native indexing operation finishes after lock or a settings change, its donation is removed before the refresh completes. Only the current profile's Core Spotlight domain is deleted. The isolated Matrix service cannot access Spotlight IPC, and no native library objects cross the renderer bridge.

## Implementation and validation

`native/macos/spotlight.mm` calls `CSSearchableIndex`, `CSSearchableItem`, attribute sets and `CSSearchQuery` through a macOS-only Node-API module. The normal macOS build compiles it using Xcode command-line tools, packages it in `Contents/Resources/native`, and registers the Spotlight activity type and URL scheme in the bundle. Windows/Linux report this integration unavailable and do not load Apple APIs.

Tests cover disabled defaults, explicit account selection, every-page scoping, exclusion of foreign/draft/trashed rows, preview opt-in, opaque stable IDs, deletion/scope replacement, empty-scope behavior, worker/native lock races, restoration after unlock, native failures, IPC isolation and the preload/UI bridge.

The dedicated [native macOS workflow](../.github/workflows/macos-native.yml) builds/packages independently of unrelated test suites. `npx tsx scripts/mac-native-integrations-audit.mjs` on a packaged macOS build seeds disposable cached mail, queries the real Core Spotlight index for donated/excluded records, waits for lock/disable removal, and uses actual LaunchServices `open` URL delivery to verify conversation restoration through app lock. The `--applescript-only` mode intentionally tests only D32 and does not validate Spotlight. The Windows development host cannot run Core Spotlight, so its local fixture results must not be described as native Spotlight acceptance. Native CI results are the authoritative platform evidence.
