# Rocket.Chat messaging

Choose **Chat → Rocket.Chat**, enter the workspace HTTPS base URL (including a deployment subpath if needed), your Rocket.Chat user ID and a personal access token. Generate/revoke the token using the workspace's personal access-token controls; workspace policies may restrict this feature. Aerio validates the identity through the authenticated profile endpoint. Reconnecting must keep the same server and user; add a separate account for another identity.

The connector lists joined public/private channels and existing direct/group conversations, reads paged plain-text history and threads, sends text/thread replies, and explicitly marks rooms read. It polls while Aerio runs. It does not create/join rooms, upload/download files, edit/delete messages, show presence/reactions, or implement Rocket.Chat end-to-end encryption. Attachments appear as filenames/titles. Read-only, broadcast and encrypted rooms cannot send; encrypted history points you to Rocket.Chat. Before any text send, Aerio refreshes room membership/encryption metadata to avoid sending plaintext based on a stale room snapshot. Server permissions remain authoritative.

HTTPS with normal certificate verification is required. Credentials never appear in URLs, redirects are refused, and requests stay beneath the configured workspace API path. The personal token is held in the OS-encrypted shared Chat vault; account display data, rooms, message pages and pending delivery records are sealed in the separate Chat SQLite database. Backups exclude these connector credentials/cache. Account identity includes the normalized workspace URL and user ID. Removing an account deletes its local credentials/cache; revoke its token on Rocket.Chat to revoke server access.

History requests 50 records per page, ordered by message time. Pagination positions and response sizes are bounded; older pages can shift if messages are inserted/deleted while browsing. Unread counts follow Rocket.Chat server preferences. Workspace rate limits pause access through the shared runtime, including across restart. Locked Aerio hides accounts/history and suppresses chat notifications.

Sending uses `chat.sendMessage` with a persisted client message ID. Responses must identify that message in the selected room. Lost/invalid responses or ambiguous server failures become **Review delivery** and are never automatically resent. Review the provider conversation before manually sending again. Server-enforced permissions or smaller workspace message limits can reject a send without discarding the draft.

Verification: adapter fixtures cover authentication and server-scoped identity, path/header transport, membership and encryption, public/private/direct endpoints, threads/history pagination, cross-room/account rejection, current-encryption checks, read markers and uncertain sends. `npx tsx scripts/provider-chat-tls-audit.mjs` runs a real authenticated local TLS fixture through the adapters and shared encrypted runtime, with two-device readback, threads, read markers and restart without ambiguous-send replay. It uses fixture credentials and does not contact live Slack/Rocket.Chat workspaces. Production server-version interoperability remains unverified.

Official APIs: [profile](https://developer.rocket.chat/apidocs/get-profile-information), [rooms](https://developer.rocket.chat/apidocs/get-rooms), [subscriptions](https://developer.rocket.chat/apidocs/get-all-subscriptions), [channel history](https://developer.rocket.chat/apidocs/get-channel-history), [private history](https://developer.rocket.chat/apidocs/get-group-history), [direct history](https://developer.rocket.chat/apidocs/dm-history), [threads](https://developer.rocket.chat/apidocs/get-thread-messages), [sending](https://developer.rocket.chat/apidocs/send-message), [read markers](https://developer.rocket.chat/apidocs/mark-channel-as-read).
