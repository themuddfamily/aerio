# GoToMeeting calendar integration

In **Settings → Online meetings**, add an OAuth client registered on [GoTo Developer Center](https://developer.goto.com/) with GoTo Meeting product access. Register the exact redirect shown by Aerio (`http://localhost:47819/oauth/goto`), save its client ID/secret, and connect the licensed organizer account in your browser. Aerio uses the current `authentication.logmeininc.com` authorization-code/token endpoints with client-secret authentication, a state-checked loopback callback and rotating renewable tokens. GoTo's documented confidential flow does not advertise PKCE, so this connector does not claim PKCE protection. Tokens/client secrets use the existing OS-encrypted meeting-host vault and stay outside backups and renderer IPC. Identity comes from the authenticated SCIM profile endpoint. See [GoTo authentication](https://developer.goto.com/Authentication) and [the token-host migration](https://developer.goto.com/guides/Authentication/New_Token_Retrieval_Migration_Guide/).

Choose **GoToMeeting** when adding a meeting to a writable Google or Microsoft calendar event. Aerio creates the scheduled meeting first and inserts its participant link/meeting number into the event notes/location before the calendar sends invitations. The organizer starts it through GoTo's normal application; Aerio never exposes a host-start URL or host token. Meetings use VoIP audio and no additional meeting password. GoTo account policies/licenses can reject unsupported choices.

Changing an Aerio-created event's title or time updates the same meeting. Removing its meeting or deleting the event cancels the provider meeting after the calendar accepts the change, unless **Keep meeting on delete** was selected. Disconnecting the host account leaves existing meetings intact. To update/cancel them afterwards, reconnect the same organizer account or manage them directly in GoTo.

Creation requires a future timed single event. Recurring/all-day meetings and local/DAV-calendar hosting are not supported by the existing hosted-meeting coordinator. GoTo subjects have a 100-character API limit; Aerio escapes angle brackets and appends a short `[aerio:…]` reference, leaving the original calendar title intact. This visible reference lets a restarted/failed request locate its upcoming meeting before trying another creation. Keep that marker until Aerio has confirmed the meeting. Do not rename/remove a still-unconfirmed marker in GoTo; doing so prevents automatic correlation. Ambiguous transport/server outcomes retain the durable creation attempt. Failed calendar writes reuse a confirmed provider meeting on retry. These recovery rules do not claim a provider idempotency key.

Verification covers the actual loopback authorization leg with a controlled token/profile API, encrypted vault persistence/renewal, API schedules and participant-link validation, title/time updates, deletion/missing meetings, explicit capability/UI setup, and real SQLite coordinator restart after an ambiguous creation with exactly one create attempt. Live GoTo organizer/calendar interoperability still requires an account. The connector follows the official [GoTo Meeting v1 API](https://developer.goto.com/GoToMeetingV1/) for create/upcoming/get/update/delete operations; it does not use deprecated token hosts.
